# Ошибки и недочеты, требующие внимания (Средний и Низкий приоритет)

Этот документ содержит описание выявленных проблем среднего и низкого приоритета, которые рекомендуется исправить для улучшения стабильности, производительности и UX приложения.

---

## 1. Отсутствие обработки типа уведомления `new_client` в Telegram-боте
* **Приоритет:** Средний
* **Компонент:** Telegram Bot (`trenerbot/internal/bot/bot_v2.go`)
* **Описание:** 
  При первой авторизации нового клиента через сайт бэкенд формирует и ставит в очередь уведомление типа `"new_client"` для тренеров:
  ```go
  _ = s.notifyCoaches("new_client", map[string]any{"user_id": uid, "name": full})
  ```
  Однако в коде бота в методе `renderNotification` отсутствует обработка этого типа. Метод возвращает пустую строку `""`, из-за чего уведомление помечается как отклонённое/ошибочное и тренер никогда не узнает о регистрации нового клиента через бот.
* **Рекомендация:**
  Добавить ветку `case "new_client":` в `renderNotification` в файле `internal/bot/bot_v2.go`.

## 2. Мерцание и постоянная перезагрузка виджета авторизации Telegram
* **Приоритет:** Средний
* **Компонент:** Frontend React (`web/src/features/auth/components/login-form.tsx`)
* **Описание:**
  Колбэк авторизации `onTelegram` передаётся в компонент `TelegramLoginButton`, но объявляется заново при каждом рендере формы `LoginForm` (например, при обновлении состояния `busy` или появлении ошибки `serverError`).
  Поскольку `useEffect` внутри виджета зависит от колбэка:
  ```typescript
  useEffect(() => { ... }, [onAuth])
  ```
  Это приводит к тому, что скрипт Telegram-виджета постоянно удаляется из DOM и скачивается/ререндерится заново, вызывая визуальное мерцание кнопки и избыточные сетевые запросы.
* **Рекомендация:**
  Обернуть функцию `onTelegram` в `useCallback` в `login-form.tsx` или убрать функцию из списка зависимостей `useEffect` в виджете, используя `useRef` для сохранения актуальной версии колбэка.

## 3. Риск падения Next.js SSR при обращении к `localStorage`
* **Приоритет:** Средний
* **Компонент:** Frontend API Client (`web/src/lib/api.ts`)
* **Описание:**
  Функции `getToken` и `getRefreshToken` напрямую вызывают `localStorage.getItem(...)`. При первой сборке или серверном рендеринге (SSR) в Next.js глобальный объект `window` (и `localStorage`) не существует, что вызовет фатальную ошибку `ReferenceError: localStorage is not defined`.
* **Рекомендация:**
  Добавить проверку окружения перед вызовом `localStorage`:
  ```typescript
  if (typeof window === 'undefined') return null;
  ```

## 4. Неоптимальный текст отмены занятия в уведомлениях `lesson_change`
* **Приоритет:** Низкий
* **Компонент:** Telegram Bot (`trenerbot/internal/bot/bot_v2.go`)
* **Описание:**
  При отмене тренировок на сервере генерируется тип уведомления `lesson_change` с `change_type: "canceled"`. Бот в дефолтной ветке выведет это пользователю как:
  `🔄 Изменение тренировки <дата> в <время> (canceled: <старое> -> <новое>)`.
  Это выглядит непрофессионально и содержит английские системные термины.
* **Рекомендация:**
  Добавить красивую обработку кейса `"canceled"` внутри `lesson_change` рендерера:
  ```go
  case "canceled":
      return fmt.Sprintf("❌ Тренировка %s %s отменена", date, timeVal)
  ```
